# Grading Workflow (instructor)

How a lab goes from twelve submitted archives to a column in the gradebook.

The rubric itself — what the ten points are for — is in [Grading & Rubrics](grading.md). This page
is the mechanics.

> [!NOTE]
> **Student IDs on this page are fabricated**
>
> `2026000001` and friends are illustrative. This repository is public, so no real 학번 appears
> here, and the files that do contain them — `course/roster-*.txt` and `course/scores-*.tsv` — are
> git-ignored.

---

## What is decided by whom

| | Points | Decided by |
|---|---:|---|
| Correctness | 4 | `lab.sh check`, automatically |
| Reproducibility | 1 | `lab.sh check`, automatically |
| **Evidence** | **3** | **You, reading the report** |
| **Understanding** | **2** | **You, reading the report** |

Half the rubric is machine-checked and it is not the interesting half. See
[how the two human scores are decided](grading.md#how-the-two-human-scores-are-decided).

## The loop

### 1. Collect

```bash
cd ~/mrider
bash scripts/lab.sh grade 1 --zips ~/Downloads/lab1
```

**Grade the archive, not the branch.** The LMS upload is the authoritative submission, so `--zips`
checks the artefact that actually counts. The archive is cut from the commit with `git archive`, so
it agrees with the branch unless someone has gone out of their way.

`--roster course/roster-2026-fall.txt` runs identical checks against git instead. It is the faster
read when you only want to see who is stuck, and the only option before the LMS deadline passes.

Output is one file per student:

```
dist/grade/lab1/2026000001.md
```

containing the submission's provenance header, the automated verdict, and a reminder of what only
you can judge.

### 2. Open the marks file

```bash
bash scripts/lab.sh scores 1
# created course/scores-2026-fall-lab1.tsv with 12 students
```

```
# uniqname	auto	evidence	understanding	late	note
2026000001	5	.	.	0	
2026000002	5	.	.	0	
2026000003	0	.	.	0	
```

`auto` is correctness + reproducibility, seeded from the automated checks — **a suggestion, not a
verdict.** Edit it if you disagree. A `0` means the checks failed or nothing was submitted.

`late` is whole days past the due date, **read from the LMS timestamp**, not the commit.

### 3. Read, and fill in

Open each `dist/grade/lab1/<uniqname>.md`, read the report it points at, and put numbers in the
`evidence` (0–3) and `understanding` (0–2) columns. A dot means *not yet read*, so you can stop
halfway and resume.

### 4. Total and export

```bash
bash scripts/lab.sh scores 1
```

```
uniqname     auto  ev  und  late  raw  final
----------------------------------------------
2026000001      5   3    2     0   10   10.0
2026000002      5   2    1     2    8    6.4  <- late
2026000003      0   0    0     0    0    0.0
----------------------------------------------
mean                                     5.5

9 not yet marked: 2026000004, 2026000005, ...

LMS upload: dist/grade/lab1/final.csv
```

Re-running never overwrites your marks and always lists who is still pending. The late policy
(−10%/day, floor 50%, zero after seven days) is applied for you.

`final.csv` is `uniqname,raw,late_days,final` — the shape a gradebook import wants.

## Where a mark lives

> [!WARNING]
> **`course/scores-<term>-lab<N>.tsv`, and nowhere else**
>
> `dist/grade/lab1/<uniqname>.md` is **regenerated by every `grade` run**, and `dist/` is
> git-ignored. A number typed there is lost twice over — once when you re-run, once when you clone
> somewhere else.
>
> The marks file is git-ignored too, deliberately: it is student grade data and this repository is
> public. **Back it up somewhere that is not this repository.**

## Adding a student mid-term

Append to `course/roster-2026-fall.txt` and re-run. The script is idempotent — it creates nothing
that already exists, and re-asserts every collaborator.

```bash
bash scripts/provision_labs.sh --dry-run    # read the account-name column
bash scripts/provision_labs.sh              # creates the repo AND sends the invitation
bash scripts/provision_labs.sh --status     # confirm it is pending, then accepted
```

There is no separate "send invitation" step: the collaborator call *is* the invitation, and GitHub
delivers it by email and on the notifications page.

> [!CAUTION]
> **End the roster with a newline**
>
> A final line with no trailing newline used to be read and then silently discarded, because
> `read` returns non-zero at EOF. The student got no repository and no invitation, and nothing said
> so — the row simply was not there.
>
> Fixed in `provision_labs.sh`, but the habit is worth keeping: after editing the roster, check the
> count.
>
> ```bash
> grep -cvE '^\s*#|^\s*$' course/roster-2026-fall.txt
> ```

## Things the LMS does to your downloads

**It renames them.** Student names get prefixed; a second copy of the same file gets `-1` appended.
Identity is therefore read from the **`Uniqname` row inside the report**, not from the filename, so
neither invents a student nor splits one in two.

**It gives you duplicates.** Two archives claiming the same uniqname are collapsed, last one
winning — which is also the right answer for a resubmission. The run prints a note when it happens.
