## Lecture

### 1. The pipeline

```
/goal_pose ──▶ bt_navigator ──▶ planner_server ──▶ path
                    │            (SmacPlannerHybrid,
                    │             global costmap)
                    ▼
              controller_server ──▶ /cmd_vel ──▶ twist_mux ──▶ controller
               (RPP, local costmap)
```

Plus `behavior_server` for recoveries, and `lifecycle_manager` bringing every node up in order.

### 2. Costmaps

| | Global | Local |
|---|---|---|
| Covers | The whole known map | A rolling window around the robot |
| Built from | The static map + obstacles | Live sensor data |
| Used by | The planner | The controller |
| Frame | `map` | `odom` |

Layers stack: `StaticLayer` (the SLAM map), `ObstacleLayer` (live scans), `InflationLayer`.

**Inflation** grows obstacles by roughly the robot's radius, so the planner can treat the vehicle as
a point. MRider instead declares a **rectangular footprint**:

```yaml
footprint: [[0.81, 0.28], [0.81, -0.28], [-0.18, -0.28], [-0.18, 0.28]]
```

Note the asymmetry — 0.81 m forward, 0.18 m back. That is not a mistake: **`base_link` is at the rear
axle**, so most of the car is in front of it. A circular-footprint approximation would be badly wrong
for a vehicle this shape.

### 3. Why the planner was replaced

`NavFn` plans on a 2D grid, as though the robot were a **free-turning point**. For a differential
robot that is nearly true. For a car it is not, and the consequence was concrete:

> NavFn routinely returned paths this car cannot drive, and RPP rejected them mid-follow with
> `detected collision ahead!` on geometry that was never feasible.

!!! quote "No controller can follow an infeasible path"

    That sentence is the whole argument. Tuning the controller could not have fixed this, because the
    fault was upstream — the path was undrivable by construction.

    Both `NavFn` and `DWB` were dropped **on geometry, without a trial run.** That is unusual and
    deliberate: when the reason is kinematic rather than empirical, running the experiment to confirm
    it would burn a week to learn what the geometry already said.

**`SmacPlannerHybrid`** searches in **(x, y, heading)** rather than (x, y), using Reeds-Shepp curves
bounded by the turning radius:

```yaml
GridBased:
  plugin: "nav2_smac_planner/SmacPlannerHybrid"
  motion_model_for_search: "REEDS_SHEPP"
  minimum_turning_radius: 1.6
  reverse_penalty: 2.5
  angle_quantization_bins: 72
```

It **cannot** return an undrivable path, because undrivable paths are not in its search space.
Reeds-Shepp curves include reversing segments; Dubins curves do not.

### 4. The two changes that only work together

`allow_reversing: true` on the controller was **inert** before the planner swap. RPP reverses only
where the *path* reverses, and NavFn never produced such a path.

!!! danger "A parameter that is on but has no effect looks exactly like one that works"

    You could have read `allow_reversing: true` in the config, believed the vehicle could reverse,
    and been wrong for as long as you liked. Nothing would have contradicted you.

    Verify capabilities by **exercising** them, not by reading configuration.

**The verified result:** a goal **2.5 m directly behind** the vehicle — geometrically impossible
forward-only at a 1.6 m turning radius. The vehicle reversed 2.1 m in a straight line, heading
unchanged at ~3°, arriving 0.40 m from the goal. Before the swap that manoeuvre had **no solution at
all**.

`reverse_penalty: 2.5` keeps reversing a last resort, for a hardware reason you know: **there is no
rear sensing.** Autonomous reverse is blind, relying on costmap memory of what was seen driving in.
Free in simulation; not free on the vehicle.

### 5. Behavior trees, and the custom ones

A behavior tree composes behaviours from reusable nodes — sequences, fallbacks, decorators — and is
re-ticked continuously, so it reacts rather than merely transitioning. Nav2 uses one to orchestrate
plan → follow → recover.

MRider overrides both stock trees. **One change:** the recovery `RoundRobin` no longer contains
`Spin` or `BackUp`.

```xml
<RoundRobin name="RecoveryActions">
  <Sequence name="ClearingActions">
    <ClearEntireCostmap name="ClearLocalCostmap-Subtree" .../>
    <ClearEntireCostmap name="ClearGlobalCostmap-Subtree" .../>
  </Sequence>
  <Wait wait_duration="5"/>
</RoundRobin>
```

- **`Spin`** — the vehicle cannot rotate in place. Not a tuning preference; it has no mechanism for it.
- **`BackUp`** — a *blind* reverse as a recovery reflex, distinct from a *planned* reversing
  manoeuvre. The planner reverses along a path it computed against a costmap. `BackUp` just reverses.
  With no rear sensing, only the first is defensible.

!!! danger "F-N2 — the symptom points at the wrong thing"

    `behavior_server` loads only the `wait` plugin. Loading a **stock** tree against it fails at BT
    parse time:

    ```
    Exception when loading BT: Action server spin not available
    ```

    `bt_navigator` is left `unconfigured`, and `lifecycle_manager` aborts bringup of the **whole**
    stack. And the symptom misleads badly:

    > planner, controller and both costmaps report **`active`** while navigation is simply absent and
    > no goal is ever accepted.

    Four out of five components report healthy. The one that failed is the one that matters, and
    nothing in `ros2 lifecycle list` makes that obvious.

    Both trees must be overridden — `bt_navigator` loads `navigate_to_pose` *and*
    `navigate_through_poses` at configure time, so fixing only the one you use still fails.

### 6. When recovery runs out

**F-N4:** given a goal 0.05 m from a wall, RPP correctly drove to it and refused the last metre. That
left the car nosed up to the obstacle, where every subsequent plan was infeasible — and with no
`Spin` and no blind `BackUp`, **there is no autonomous way out.**

Recovery on this platform is: clear the costmaps, wait, and then **a human takes the RC sticks**.
That is not a gap in the software. It is [the authority ladder](../../design/safety.md) doing its
job — the last layer of recovery is a person, by design.
