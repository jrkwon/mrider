# What is allowed to differ

| | Twin | Vehicle |
|---|---|---|
| Hardware plugin | `gz_ros2_control` | `mitt_hardware` |
| Clock | `use_sim_time:=true` | `use_sim_time:=false` |
| ROS domain | 0, localhost only | **10 + N** |
| Sensor data | Gazebo bridges | Drivers, and the Teensy through the agent |

Four rows. **Nothing else.**

When the vehicle behaves differently: which row is it,
and what else differs that should not?

# `use_sim_time` fails without an error

Every launch here defaults to `use_sim_time:=true`.

On the vehicle nothing publishes `/clock`.
A node on simulated time sits at **time zero**:
transforms "too old", costmaps empty, and no log line says why.

```bash
ros2 param get /controller_server use_sim_time
```

# The vehicle number, in three places

```bash
MITT_VEHICLE=2 source ros2_ws/setup_env.sh
ros2 launch mitt_bringup real.launch.py vehicle:=2
ros2 launch mitt_navigation nav2.launch.py vehicle:=2 use_sim_time:=false
```

`real.launch.py` refuses the wrong domain.
`nav2.launch.py` prints **`WRONG VEHICLE`** when the body differs.

A planner sized for another car plans paths yours cannot follow.

# Calibration is a file, with a date on it

| | Artifact | Stale when |
|---|---|---|
| Steering zero, scale | `calibration/steering.yaml` | Sensor or linkage re-mounted |
| Drive odometry | `calibration/odom.yaml` | Tyres or payload changed |
| Camera intrinsics | `calibration/camera_front.yaml` | Lens refocused |
| Extrinsics | URDF joints | **The mast was moved, even slightly** |
| Geometry | `vehicles/vehicle<n>.yaml` | The chassis changed |

A LiDAR that moved 3 cm gives doubled walls and no error message.

# Record the run, or it did not happen

```bash
ros2 bag record -o merge3_teleop /mitt/dbw/status \
    /mitt/dbw/command /cmd_vel /tf /tf_static /scan
```

With every bag: fork commit, firmware commit, vehicle number,
battery voltage, operator.

**Record the failures too.** That bag is what your
failure analysis is graded on.
