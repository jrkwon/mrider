# The acceptance gates

| Gate | Target |
|---|---|
| Build and test | Clean; tests that are not linters |
| `/mitt/dbw/status` | ≥ 50 Hz; 0 USB dropouts over ≥ 30 min |
| Joystick to wheel | ≤ 100 ms at p95 |
| Twin against vehicle | Within 10% |
| Odometry | ≤ 2% over 20 m; ≤ 5° after a figure-8 |
| SLAM | ≥ 30 m loop; walls within 10 cm |

**Missing a gate is a result.** An unmeasured gate is nothing.

---

# A gate is a number, a procedure and a condition

Not: *"odometry drift is under 2%."*

> Drift 1.6% (0.32 m over 20.0 m), mean of five runs, range 1.1–2.3%.
> Corridor, tape-measured, 0.4 m/s, vehicle 2 at fork commit `abc1234`,
> 12.6 V at the start. Bags in `bench/odom_2026-12-12/`.

The number **with its spread**, the trials, the procedure,
the conditions, the raw data. One run is an anecdote.

# A failure analysis, in five lines

| | |
|---|---|
| **Observed** | What a sensor or a log showed. Not "it crashed" |
| **Subsystem** | Which track's part was responsible |
| **Evidence** | What localised it there, and ruled the others out |
| **Change** | What you did about it |
| **Outcome** | Before and after. "Not fixed" is an outcome |

Naming a cause without ruling out the others is a guess.
